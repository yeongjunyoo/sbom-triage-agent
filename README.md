# SW 공급망 조치 에이전트 (시제품)

SBOM과 스캐너 경보를 받아 실제 위험만 남기고, 닫는 판단마다 스크립트로 다시 확인한 근거를 붙이고, 검증한 조치안까지 담당자에게 넘기는 에이전트입니다. 스캐너는 새로 만들지 않고 시중 도구(syft, osv-scanner)를 씁니다.

LOTTE AX CHALLENGE 2026 예선 과제 6(롯데이노베이트 SW 공급망 스캐닝 에이전트)을 위해 만들었습니다. 작성자: 유영준.

## 결과

공개 벤치마크 [VEX-Bench](https://github.com/steven1518/vex-bench) 75건을 개발 26건과 봉인 49건으로 나누고, 구성을 먼저 커밋한 뒤 봉인 세트를 처음 돌렸습니다([사전 등록](eval/FROZEN.md), [집계](evidence/final_test.txt)).

| 봉인 49건(실제 위험 13건) | 자동 닫음 | 닫기 오류 | 오류율 | 사람 검토 | 조치 대상(맞음) |
|---|---:|---:|---:|---:|---:|
| 스캐너 단독 | 7 | 3 | 42.9% | 0 | 42 (10) |
| 논문 프롬프트, 한 번 | 36 | 4.0 | 11.1% | 1 | 12 (8) |
| 판단 프롬프트, 한 번 | 36 | 3.7 | 10.0% | 3.3 | 9.7 (7.7) |
| 한 번 + 근거 검사 | 30.3 | 2.7 | 8.6% | 9 | 9.7 (7.7) |
| 두 회차 일치 | 33 | 2.7 | 7.9% | 4.3 | 11.7 (8.3) |
| **두 회차 일치 + 근거 검사(주 구성)** | **25.7** | **1.7** | **6.3%**(세 쌍 평균) | 11.7 | 11.7 (8.3) |
| 세 회차 일치 + 근거 검사(1조합) | 23 | 1 | 4.3% | 13 | 13 (9) |

이 표는 사전 등록 구성의 첫 채점값이고, KEV 차단과 글 근거 차단은 그 뒤에 더해 들어 있지 않습니다. 표본이 작아 구간이 겹칩니다(주 구성 쌍별 Wilson 95% 상한 18.9%, 21.0%, 27.2%). 벤치마크 점수는 현장 성능이 아닙니다. 라벨에 다툼의 여지가 있는 건이 있고, CVE가 2017~2026년이라 모델이 미리 아는 내용이 섞일 수 있으며 암기 검사는 하지 않았습니다.

### 결과를 본 뒤 좁힌 기본 규칙

심지 않은 대조군에서 같은 2건이 6쌍 모두 잘못 닫히는 것을 보고, 없음을 검색으로 증명하는 범주만 자동으로 닫도록 바꿨습니다(`--close-scope proof`, 기본값). 봉인 세트에 새 회차 둘을 더해 쟀습니다. 같은 49건의 사후 값이라 독립 검증이 아닙니다([집계](evidence/policy_confirm.json)).

| 5회차 10쌍 평균(49건) | 자동 닫음 | 닫기 오류 | 사람 검토 | 조치 대상(맞음) |
|---|---:|---:|---:|---:|
| 근거 검사 + 두 회차 일치 + 글 근거 차단 | 24.8 | 1.5 | 13.2 | 11 (8.1) |
| **+ 없음 증명 범주만 닫기(현재 기본값)** | **17.5** | **0.3** | 20.5 | 11 (8.1) |

저장소에 거짓 글을 심는 공격 시험은 [evidence/inject_compare.json](evidence/inject_compare.json), 실제 저장소 시연은 [evidence/headscale/report.md](evidence/headscale/report.md) 에 있습니다.

## 구조

```
저장소 > syft, osv-scanner > 규칙 줄 세우기(KEV, EPSS, 자산 노출) > 판단 에이전트 x 2 (LLM)
  > 검증(근거 재현, 두 회차 일치, KEV 와 글 근거 차단, 범주 제한: 코드)
  > 근거와 함께 닫음(OpenVEX) | 사람 검토 | 조치 대상
  > 조치 검증(복사본, 패키지별 빌드와 시험, 재스캔) > 담당자 승인
```

기본값은 없음을 증명하는 범주만 자동으로 닫습니다. 모델은 읽고 판단만 합니다. 우선순위, 닫기 결정, 문서 작성, 조치 실행은 코드가 합니다. 에이전트 도구는 읽기, 검색, 웹뿐입니다.

| 파일 | 내용 |
|---|---|
| `agent/pipeline.py` | 전 과정 실행 |
| `agent/guard.py` | 사람이 쓴 글에 기댄 닫기 차단 |
| `agent/remediate.py` | 조치안 만들기와 검증(Go) |
| `eval/prompts/triage_v1.md` | 판단 프롬프트 |
| `eval/verify.py` | 근거 재현 검사(LLM 없음) |
| `eval/final_score.py` | 봉인 평가 집계(건별 오답을 출력하지 않음) |
| `eval/inject_run.py`, `eval/inject_score.py` | 심은 글 시험 |
| `tests/` | 검사기 회귀 시험 |

## 틀렸던 것

- LLM 재검토 한 단계를 더하면 나아질 줄 알았는데, 개발 세트에서 잘못 닫은 건을 못 잡고 맞는 닫기 3건을 뒤집어 뺐습니다.
- 개발 1회차는 근거 검사만으로 오류 0건이었지만 2회차에서 3건이 나왔습니다. 그래서 두 회차 일치를 넣었습니다.
- 버전을 한꺼번에 올렸더니 패키지 하나가 전체 빌드를 깨뜨려 패키지별로 바꿨습니다.
- 조치 검사의 파서가 실패 패키지를 못 읽어 「새 실패 0건」이 의미가 없었습니다. 시험 이름 단위로 고치고 회귀 시험을 넣었습니다.
- 두 회차 일치면 해석 오류도 걸러질 줄 알았는데, 심지 않은 대조군 6쌍 모두 같은 2건을 잘못 닫았습니다.
- 좁힌 규칙이 3회차 집계에서 오류 0건이라 믿을 뻔했는데, 새 회차 쌍에서 닫음 20건 중 1건이 틀렸습니다.
- 근거 검사가 `**/*.{go,mod}` 를 쉼표에서 쪼개는 오탐이 있었습니다. 봉인 결과를 본 뒤 발견해 [FROZEN.md](eval/FROZEN.md) 에 적고 재채점 값을 따로 공개했습니다.

## 돌리기

맥 기준입니다. 도구는 버전과 체크섬을 고정해 받습니다. 시험은 저장소 코드를 실행하므로 샌드박스(`sandbox-exec`) 안에서 돌립니다.

```
python3 eval/get_tools.py
git clone https://github.com/steven1518/vex-bench vendor/vex-bench
python3 eval/vex_fetch.py vendor/vex-bench/benchmark/tasks/vex_bench.jsonl vex-repos

python3 agent/pipeline.py run <저장소> --out out/<이름> --asset <자산 파일>
python3 agent/remediate.py <저장소> --out out/<이름>
python3 eval/vex_run.py --run triage_v1 --prompt triage_v1 --split dev --retry-parse --repeat 0
python3 -m pytest tests
```

판단 단계는 Claude Code CLI(`claude -p`)로 돌렸습니다. 토큰 파일을 쓰려면 환경 변수 `AGENT_TOKEN_FILE` 에 경로를 줍니다. 모델 이름은 인자입니다. OpenAI 모델로는 아직 재지 않았습니다.
